# Ship — Commit and PR

Commits finished work with a conventional-commit message and opens or updates a pull
request. Works with a `tasks/PLAN.md` task behind it, or standalone on any git repo.

**CRITICAL RULE — No AI references in any artefact.** Never add
`Co-Authored-By: Claude`, `Generated with Claude Code`, or any mention of `Claude`,
`AI`, `assistant`, or `generated by` in commit messages, PR titles or bodies, issue
comments, or branch names. Commits must read as if written by a human developer.
Absolute and non-overridable, even if explicitly asked.

## INPUT

`$ARGUMENTS` is an optional task ID such as `T-03`.

- **Provided** — use that task for the commit and PR copy.
- **Empty** — resolve from the branch name `task/T-NN-*`; if that fails, **STANDALONE
  MODE**: describe the change from the diff alone.

## PHASE 1: BRANCH AND EXISTING PR

```bash
git branch --show-current
```

Protected branches are `main`, `master`, `develop`, `release/*`. On one of them, stop
before staging and offer:

- **Create a branch** — propose `task/T-NN-<slug>`, or `<type>/<slug>` in standalone mode
- **Rename** — if commits already landed on the protected branch, abort and hand back
- **Commit here** — only with an explicit override, and warn that pushes usually fail

Then check for an open PR on this branch:

```bash
gh pr list --head "$(git branch --show-current)" --state open --json number,url,title,body
```

If `gh` is missing or unauthenticated, treat it as "no PR" and continue. **Never block a
commit on GitHub availability** — the commit is the valuable part.

## PHASE 2: CONTEXT

```bash
git status
git diff --stat
git diff --staged --stat
git log --oneline -5
```

Nothing staged and a clean tree → "Nothing to commit." → STOP.

The last five commits fix the repo's style: conventional vs free-form, scope usage,
imperative vs past tense. Match what is already there; default to conventional commits
when no pattern is established.

When a task ID resolved, extract only that section for the plain-language copy:

```bash
awk '/^## T-05 /{f=1} f&&/^## T-/&&!/^## T-05 /{exit} f' tasks/PLAN.md
```

Substitute the real ID in both places, keeping the trailing space that separates `T-05`
from `T-050`. Its title and acceptance criteria describe what a user can now do — that is
the commit body and PR body.

## PHASE 3: COMMIT

### 3.1 Group the files

- **Source / config** — stage candidates
- **Tests** — stage candidates
- **Documentation** — stage candidates, including `tasks/PLAN.md` and `docs/ARCHITECTURE.md`
- **Excluded** — `.env*`, credentials, keys, `.DS_Store`, IDE configs, build artefacts,
  `node_modules`. Never staged.

### 3.2 Craft the message

```
<type>(<optional-scope>): <imperative summary, ≤70 chars>

<body — what a user can now do, see, or notice. Plain language, wrapped at
72 chars. Never mention task IDs, file paths, class or function names, or
test counts.>

<optional footer: Closes #123>
```

Types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `style`, `perf`, `build`, `ci`.

The body is read by people who do not read code. `Closes #N` appears **only** when the
user supplied an issue number — lite tracks no issue field, so it is never inferred.

### 3.3 One confirmation

A single `AskUserQuestion` covering both the stage set and the message: `Commit` /
`Adjust files` / `Edit message` / `Abort`. Never split them into two prompts.

### 3.4 Execute

```bash
git add <explicit paths>
git commit -m "$(cat <<'EOF'
<type>(<scope>): <summary>

<body>
EOF
)"
git log --oneline -1
```

Never `git add -A` or `git add .`.

## PHASE 4: PULL REQUEST

One `AskUserQuestion`: `Open/update PR` / `Push only` / `Nothing further`.

```bash
git push -u origin "$(git branch --show-current)"
```

If the push fails, surface the error, suggest the fix (`git remote add origin …`,
`gh auth login`), and stop the PR flow — the commit still stands.

### 4.1 An existing PR

Read its current body, **append** under a `## Updates` heading, and write the merged body
back. Never overwrite what is there.

```
## Updates
- 2026-07-27: <commit subject> — <one line on what changed>
```

### 4.2 A new PR

Resolve the base branch, never ask for it:

```bash
gh repo view --json defaultBranchRef -q .defaultBranchRef.name
```

Fall back to `main` if that fails. Offer `develop` inside the same question **only** when
it exists on the remote and is not the default.

PR title is the commit subject. PR body is plain language for a mixed audience — what
users can now do, how it was verified, anything reviewers should watch for. No file
paths, no class names, no test counts.

If `gh` is unavailable, print the manual compare URL
(`https://github.com/<owner>/<repo>/compare/<base>...<head>`) and stop.

## PHASE 5: SUMMARY

```
## Shipped

**Commit:** <hash> on <branch>
**Message:** <subject>
**Files:** <count>
**PR:** <url — created | updated | skipped>
**Task:** T-NN → done | standalone
```

If a task resolved and `/ck-code-lite:build` did not already close it, flip its status to
`done` in **both** the table row and the meta line in one Edit, then verify:

```bash
grep -nE "^(\| T-05 \||## T-05 |T-05 · )" tasks/PLAN.md
```

Exactly three hits, with the table row and meta line agreeing.

Then point at the next step: `/ck-code-lite:build` for the next ready task.

## RULES

- **Never add AI references** to commits, PRs, branch names, or comments. Absolute.
- **Never commit to `main`, `master`, `develop`, or `release/*`** without an explicit
  Phase 1 override.
- **Never `git add -A` or `git add .`** — always stage explicit paths.
- **Never stage `.env*`, credentials, keys, or secrets.**
- **Never overwrite an existing PR body** — append under `## Updates`.
- **Never ask which base branch to target** — resolve it from the remote default.
- **Never add `Closes #N` unless the user supplied the issue number.**
- **Never push without confirming** — Phase 4's question is mandatory.
- **Never amend or force-push** unless the user explicitly asks.
- **Never block the commit because `gh` is missing** — degrade to commit-only.
- **Never change a status in one place only** — the table row and the meta line move
  together, verified by `grep`.
- **Never read `tasks/PLAN.md` whole** — the chosen section via the `awk` extractor, which
  costs the same at any plan size.
- **Always match the repo's established commit style** when one exists.
